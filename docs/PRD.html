产品愿景与痛点突破 (Executive Summary)

当前的静态网页应用（index.html + oral_coach.js + learning.js）已经具备丰富的旅行场景、Top 200 动词、N5–N3 语法与本地语音识别对齐。但由于受限于纯前端无后端的静态部署形态，目前的 AI 教练仍停留在「单轮录音 → 静态文字打分」阶段，与 LanguaTalk (Langua AI) 或真实真人日语外教相比，存在四大结构性差距：

❌ 当前瓶颈（单轮文字反馈）
  • 老师不会「开口说话」，只能看文字点评，无法听见错误与正确发音的直观对比。
  • 缺少连续引导：读错一个促音或助词后没有自动追问、拆词慢读、要求重读直到达标。
  • 自由对话缺少双语救场、实时纠错与口头造句替换训练（パターンドリル）。
  • 长文本无法点击任意单词查看假名/辞书形/音调并一键存入长期记忆。
✅ 目标体验（Nihongo Sensei AI 私教平台）
  • 会开口的中日双语真人私教：用自然亲切的中文讲解「为什么错」、用标准东京音示范正确读法，并播放你自己的录音作对比。
  • 零决策疲劳的 10 分钟私教课：老师主动带节奏（复习热身 → 句型替换 → 情景对话 → 故事复述）。
  • LanguaTalk 级实时语音通话：<600ms 低延迟自然对话 + 随时插话打断（Barge-in）+ 异步后台逐句纠错。
  • 全平台与持久记忆：引入 FastAPI 后端（本地开发 / Google Cloud Run 部署），跨设备同步学习进度、易错习惯账本与 FSRS 闪卡。

3

核心教学法设计：像顶级真人日语老师一样教学

顶级 1 对 1 日语老师与普通聊天机器人的本质区别在于：老师主导课堂节奏、拒绝无效夸奖（不会在你发音错误时盲目说「上手ですね！」）、逼出主动口语产出，并在错误发生时当场示范并陪你练到过关为止。

3.1 零决策疲劳：10 分钟结构化每日私教课 (Guided Daily Lesson)

Stage 1 · 1–2 min
🔁 记忆热身唤醒
老师根据 Sensei's Notebook 自动抽查 2–3 个昨天卡壳的句子或今日到期的 FSRS 词汇，通过中文提问逼你开口回忆日语表达，答对立即进入新课。
Stage 2 · 3 min
⚡ 微讲解 + 替换操练
双语讲解 1 个今日语法点（如 〜ていただけますか），先跟读过关，随后进行口头槽位替换（パターンドリル）：不看屏幕，现场把「拍照」换成「放行李」并变形说出。
Stage 3 · 4 min
🎭 实战情景 + 敬语抗压
老师切入真实日本店员/朋友角色（使用地道高速口语与敬语），中途加入突发小状况；卡壳时允许说中文/英文触发双语安全网，学会后再继续演练。
Stage 4 · 1–2 min
🎧 复盘与故事巩固
老师口头总结今日 1 个发音习惯与 1 个高频收获；课后一键生成包含今日生词的 90 秒多角色分级音频故事，支持「听完用日语复述给老师听」。

3.2 「原声对比 → 拆解纠因 → 标准示范 → 练到过关」闭环 (Audio Mirror Loop)

实时语音模型（gemini-3.8-live）自身为了对话流畅往往过于宽容，且 AI 难以用嘴巴精确模仿你的错误腔调。本系统通过后端音频缓存实现比真人更精准的「声学镜子（Audio Mirror）」机制：

图 1：Audio Mirror + Repeat-Until-Good 闭环（仅在局部词块真听出提升后才放行下一句）
🎙️ 实战课堂音频脚本示例（酒店行李寄存场景）：
学生试读 #1
「すみません、大きいスーツケースを預けたいです」（语调偏平，且「預けたいです」略显生硬）
🔊 声学回放
老师先说：「先听一下你刚才后半句的录音——」→ 播放学生自己刚才录下的 1.8 秒切片
老师双语纠偏
「听出来了吗？有两个小地方可以更好：①『預けたい』重音在 た 前，要在『た＼い』往下降：あずけた＼い；② 对酒店前台提请求，句尾加上『〜のですが』会礼貌柔和很多：預けたいのですが。来，先把『預けたいのですが』慢速跟我读一遍！」
学生跟读 #2
「預けたいのですが」（麦克风自动重开，gemini-4-argon 专项复检音调与句尾柔和度）
老师验收过关
「太棒了！这次『た＼い』的降调和委婉语气非常地道！那现在挑战一下完整句，顺便把箱子换成『婴儿车（ベビーカー）』试试看怎么说？」

3.3 五维语言肌肉协同训练体系 (Beyond Pronunciation)

训练维度 教学互动方式 核心练习内容与目标
1. 发音与东京音调 Audio Mirror 对比 + 局部词块微操练 高低音调（平板型/中高型/头高型）、促音 っ 停顿、长音两拍时长、清浊音、ら/つ/ん 舌位。
2. 口头反射变形 口头槽位替换操练（パターンドリル） 不看文字选择题，听老师提示在 1 秒内口头完成 ます / て / た / ない / たい / ば 动词变形与助词切换。
3. 语法与敬语分寸 Flow 静默气泡 vs Tutor 口头打断纠错 区分 は/が、に/で、から/ので、以及面向家人（タメ口）vs 店员/保育园（丁寧語/謙譲語）的得体切换。
4. 真实听力抗压 店员真语速敬语解码 + 听不清救场训练 训练听懂日本高频店员词（お召し上がり・温めますか・お預かり），并习惯脱口而出「もう少しゆっくりお願いします」。
5. 叙事与开放表达 自由对话 + 分级故事听后复述（Retell） 听完 60–90 秒包含自己生词的日语故事后，用自己的话向老师复述梗概，培养 〜てから / 〜おかげで / 〜のに 长句串联力。

系统架构与实测 Gemini 模型矩阵

后端 API 契约与数据库设计 (server/)

5.1 核心 REST & WebSocket 接口规范

Endpoint 方法 / 协议 职责与输入输出契约
/ws/live WebSocket 客户端发送：16kHz Int16 PCM 二进制帧 + JSON 控制消息（start_session, barge_in, hint_request, slow_down, correction_mode）。
服务端返回：24kHz PCM 二进制音频帧 + JSON 事件（transcript_user, transcript_ai, tokens, turn_correction, interrupted）。
/api/sensei/turn POST (Multipart / JSON) 用于「10 分钟私教课」与「练到过关纠音模式」：接收目标句、课前状态机阶段（WARMUP | TEACH | SHADOW_DRILL | SUBSTITUTION_DRILL | WRAPUP）、尝试次数与 16kHz WAV，返回 gemini-4-argon 严格评分、decision: pass | retry_chunk | retry_full | advance、错词片段及对应私教语音 URL（由 3.8-flash-lite-tts 生成）。
/api/tts POST / GET 入参：text, style (teacher_bilingual | slow_clear | native_normal | casual), voice, model。
通过 SHA-256 查本地磁盘或 GCS 缓存；未命中调用 gemini-3.8-flash-lite-tts 或 3.8-flash-tts，返回可 Range 播放的音频 URL。
/api/dict/tokenize POST 使用 SudachiPy（sudachidict_core）将任意日语句子切分为词素列表，匹配 JMdict 中/英释义 + JLPT 等级 + Kanjium 音调番号，支撑全站任意气泡「点词查意 + 存入闪卡」。
/api/sessions/{id}/report POST 调用 gemini-4-neon 汇总整场对话，生成流利度/音调/敬语评分、Top 3 反复错误总结与待复习词单，并写入 weakness_memory。
/api/stories/generate POST 抽取 5–8 个到期或收藏的 FSRS 词汇 + 目标级别（N5/N4/N3），gemini-4-neon 创作双人或旁白故事，gemini-3.8-flash-tts 合成音频并返回分段时间戳 + 分词。
/api/srs/cards
/api/srs/review		 GET / POST 基于 py-fsrs 的跨设备统一记忆本 CRUD 与调度接口，支持翻卡回忆、听音辨意、完形填空、口头产出四种考法，并兼容导入现有 localStorage 数据。

分阶段开发路线与验收标准 (Phased Roadmap)

Phase 1 · FastAPI 核心后端 + 「练到过关」双语口语私教与替换操练 MVP 优先落地
  • 交付模块：server/main.py, server/config.py, server/db.py, server/services/sensei_engine.py, server/services/tts_service.py, sensei_ui.js，接入现有 Web 前端新增「🧑‍🏫 AI 私教课」标签页。
  • 核心功能：实现图 1 完整「用户原声镜子回放 → gemini-4-argon 严格纠音 → gemini-3.8-flash-lite-tts 双语讲解与示范 → 自动重录复检直到达标」闭环，以及面向 Top 200 动词的口头槽位替换操练。
  • 验收标准：故意漏读促音 っ 或错用助词时，老师必须播放原声、讲清原因、拆出错误词块带读，且至少在重读达标后才放行下一句。
Phase 2 · 实时语音通话模式 (gemini-3.8-live) + 双轨纠错 + 手机端防回音 LanguaTalk 核心体验
  • 交付模块：server/services/live_relay.py, live_audio_worklet.js，升级 Call Mode UI。
  • 核心功能：16kHz/24kHz 实时 WebSocket 语音通话（含 18 个旅行场景人设 + 日常闲聊）、随时打断插话（<200ms 截断播音）、中文/英文卡壳救场、异步 gemini-4-argon 气泡纠错卡片、Flow vs Tutor 模式切换、iPhone Safari 外放防回音开关与「💡 帮我接话 / 🐢 慢点说」快捷按钮。
  • 验收标准：连续对话 5 轮以上，AI 语音首字响应延迟 <800ms；对话中说中文求助能被自然纠正后接续角色扮演；每轮 7 秒内气泡自动浮现精细修改建议。
Phase 3 · 词典级点词查释义 + Sensei 记忆本 (FSRS) + 10分钟引导课程 & 战报 体系化沉淀
  • 交付模块：server/services/jp_tokenizer.py (SudachiPy + JMdict), server/services/lesson_planner.py。
  • 核心功能：所有对话气泡与课程文本支持点击任意单词弹出释义/音调/一键存卡；py-fsrs 四模式复习；完整 4 阶段 10 分钟引导课状态机与挂断后战报生成，并将高频薄弱点自动注入下次课程提示词。
  • 验收标准：点击复杂活用词（如「預けておきました」）能准确还原辞书形「預ける」并一键加入 FSRS；下一次开课时老师在热身环节主动抽查上节课保存的新词。
Phase 4 · 个性化分级故事复述 + Cloud Run 上线 + 移动端/桌面端打包 全端发布
  • 交付模块：server/services/story_service.py, server/Dockerfile, deploy_cloudrun.sh，以及可选的 capacitor.config.ts (iOS/Android) 与 src-tauri/ (Mac/Win)。
  • 核心功能：利用 gemini-4-neon + gemini-3.8-flash-tts 生成包含本周生词的多角色分级故事（支持听后口头复述打分）；家庭专属口令/OAuth 鉴权部署至 Cloud Run（--timeout=3600 支持长时 WebSocket）。
  • 验收标准：Haodong 与 Sherry 可分别在手机与电脑端登录同步各自记忆本与通话记录，外网 HTTPS 下手机 Safari / Capacitor 通话稳定不掉线。

非功能指标、关键工程避坑清单与验证方案

7.1 性能、安全与成本指标

  • 延迟目标：Live 通话端到端响应 <800ms；Barge-in 本地播音打断 <50ms；TTS 命中缓存 <40ms，未命中 <3.5s（3.8-flash-lite-tts）；异步纠错气泡 <7s（gemini-4-argon）。
  • 安全性：GEMINI_API_KEY 仅存于后端环境变量 / Cloud Secret Manager，前端通过 HttpOnly Cookie 或家庭口令 Bearer Token 鉴权，彻底杜绝前端密钥泄露。
  • 成本控制：所有系统高频示范音与故事音频均按 SHA-256(model, voice, style, text) 落盘缓存；裁判模型固定开启 thinkingLevel: "LOW"；保留现有本地 audio/*.mp3 作为 18 个旅行场景的零成本离线保底。
⚠️ 实测已踩过的 4 个关键技术避坑清单 (Verified Pitfalls)
  1. TTS 模型严禁传 systemInstruction 或在正文拼英文提示词：实测 gemini-3.8-flash-lite-tts 若传入 systemInstruction 会直接报错 HTTP 400 (Developer instruction is not enabled for this model)；若把 "Speak like a warm Japanese teacher..." 拼在 contents 文本开头，模型会把英文提示词也朗读出来！正确做法：不传 systemInstruction，仅在 contents 中传入纯净的自然中文+日语口语台词（实测已验证发音完全自然，2.62s 返回完整 audio/wav）。
  2. 浏览器不可发送 Api-Revision 请求头：实测 Google CORS 预检对 /v1beta/interactions 带 Api-Revision 会直接返回 HTTP 403；统一由 FastAPI 后端调用标准 generateContent（REST）与 bidiGenerateContent（WSS）。
  3. Live 长通话防断连配置：必须启用 ContextWindowCompressionConfig(sliding_window=...) 与 SessionResumptionConfig，并在 Cloud Run 设置 --timeout=3600（WebSocket 默认仅 5 分钟超时）。
  4. 打断瞬间清空环形缓冲：收到 Gemini Live 的 serverContent.interrupted 或用户主动按插话键时，必须立即对所有已排队的 AudioBufferSourceNode 调用 .stop() 并重置播放游标，否则 AI 仍会多念 1–2 秒旧音频。

7.2 验证与测试计划 (Verification Plan)

  • 后端单元测试 (pytest server/tests/)：验证 tts_service 缓存命中及音频头部合法性（确保无英文提示词误读）、sensei_engine 对不同错误类型的分级判定（pass vs retry_chunk）、jp_tokenizer 对复杂活用词还原准确度。
  • 实时音频端到端实测：本地启动 uvicorn server.main:app，验证桌面 Chrome 与 iPhone Safari 真机（AirPods 耳机模式 + 外放防回音模式）完成 5 轮连贯通话、插话打断、中文求助、声学镜子对比与 FSRS 存卡全链路。
